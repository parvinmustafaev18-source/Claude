# Инструкции Codex для MeshPlugin

## Проект и совместимость

MeshPlugin строит КЭ-сетку фундаментной плиты в AutoCAD и экспортирует схему
в текстовый формат ЛИРА-САПР. Рабочий проект — `MeshPlugin.csproj`.

- Текущий стек: C# 7.3, .NET Framework 4.8, x64.
- Исходная версия API — AutoCAD 2019; в контексте проекта также описана работа
  с AutoCAD 2024. Автоматический поиск папки установки не доказывает
  совместимость с каждой найденной версией AutoCAD.
- Сохраняй текущие версии языка, платформы и зависимостей в обычных задачах.
  Миграцию выполняй, когда она входит в задачу пользователя.
- Для ссылок на `accoremgd`, `acdbmgd`, `acmgd` сохраняй `Private=False`.

## Контекст перед изменениями

1. Проверь `git status` и существующие изменения в рабочей копии.
2. Прочитай относящиеся к задаче разделы `CLAUDE.md`: принятые решения,
   жёсткие правила, известные дефекты и результаты проверок. Этот файл хранит
   контекст проекта и для Codex; его примеры локальных Git-команд не заменяют
   рабочий процесс облачной задачи.
3. Используй `README.md` для пользовательских команд, установки и сборки.
   При расхождении документации проверь код и более поздние записи контекста.
4. При работе с плагином прочитай
   `.claude/skills/autocad-mesh-plugin-workflow/SKILL.md` и нужный справочник
   из его папки `references/`. Этот навык можно читать по указанному пути;
   перенос в `.agents/skills` для этого не требуется.

Ищи нужные функции через `rg`; затем читай соответствующий участок исходника.
Номера строк в справочниках могут устареть — ориентируйся также на имена функций.

## Правила реализации

- Сохраняй разделение расчётных ядер `MeshCore.cs` и `ExportCore.cs`
  и команд AutoCAD, которые читают чертёж, спрашивают параметры и выводят результат.
- Единицы чертежа — миллиметры. Соблюдай жёсткие правила из `CLAUDE.md`
  и инварианты профильного навыка; не ослабляй их ради успешного самотеста.
- Пользовательские команды используют префикс `LIR`, самотесты — `MP`.
  Сообщения команд пиши по-русски, с полезными числами и понятной причиной ошибки.
- Сохраняй существующую обработку отмены и отката транзакций. Проверяй контекст
  документа и необходимость его блокировки при добавлении новых точек входа.
- Для формата ЛИРА используй `LiraExport.cs`, `ExportCore.cs`, проверки экспорта
  и подтверждённые сведения из контекста. Различай проверку структуры текста
  и фактический импорт в ЛИРА-САПР.
- При добавлении команды, слоя или этапа расчёта обновляй соответствующий
  справочник. Новые решения и результаты воспроизведения записывай в `CLAUDE.md`.
- Исходник инструкции Word — `docs/make_instruction.js`; документ `.docx`
  обновляется его пересборкой.
- Файлы `.bat` сохраняй в CP866 с CRLF, как требует существующая настройка проекта.
- `audi-legend`, навыки Remotion/mediabunny и `skills-lock.json` относятся
  к другому проекту и сохраняются по решению пользователя. Не меняй их
  при работе над MeshPlugin.

## Сборка и проверки

На Windows с AutoCAD и Visual Studio/MSBuild:

1. Закрой AutoCAD и запусти `build.bat`. Для отдельной сборки доступна команда:
   `MSBuild.exe MeshPlugin.csproj /p:Configuration=Debug /p:Platform=x64`.
   При необходимости передай путь к библиотекам через `/p:AcadDir="..."`.
2. Открой AutoCAD, выполни `LIRVERSION` и сверь штамп/путь загруженной DLL.
3. Проверь изменённый сценарий. Для изменений ядра используй `MPTEST`
   с записанными числом планов и первым seed. Воспроизводи сбой через
   `MPTESTCASE` в пустом тестовом чертеже: команда рисует план в активном документе.
4. Сравнивай результаты на одинаковых seed. Известные провалы описаны
   в `CLAUDE.md`; указывай отдельно прежние дефекты и новые изменения результата.

`accoreconsole.exe` из установки AutoCAD можно использовать для совместимых
проверок без графического интерфейса; это также требует установки AutoCAD.

В облаке сначала проверь наличие нужных инструментов и библиотек.
Если сборка или запуск AutoCAD недоступны, выполни доступные проверки кода
и изменения через `git diff --check`, затем дай конкретный сценарий проверки
на Windows. Не выдавай непроведённую сборку, самотест или импорт в ЛИРА за успешные.
Обновляй `dist/MeshPlugin.dll` только результатом реальной сборки.

## Работа через веб-версию

Работай в предоставленной ветке задачи и сохраняй чужие изменения.
Используй процесс сохранения изменений и PR, принятый в текущей задаче;
локальные скрипты синхронизации из `CLAUDE.md` рассчитаны на Windows-компьютеры.
В итоговом ответе укажи, что изменено, какие проверки действительно выполнены,
и что осталось проверить в AutoCAD или ЛИРА-САПР.
